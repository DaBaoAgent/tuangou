# 团购「代码画视频」管线方案

> 版本：v1（2026-11-16）
> 目标：在 `Auto-Video` 里新建一条**纯代码绘制**的团购带货管线（竖屏 1080×1920 / 30fps / 15s），做到
> **1 秒内出钩子、文案自动生成、音色按品类自动选、成片自动进发布队列**。
> 本文是制作方案（调研结论 + 设计 + 分批实施 + 验收 + 风险），不是已完成的代码。

---

## 0. 结论先行

1. **定位**：这条管线不是「探店实拍」的替代品，是**「信息解释型」AIGC 团购片**——用价签、份量、套餐拆解、到店路径讲清「这单值不值」，属于平台允许、但必须声明的 AIGC 营销内容。定位错成「我替你去吃了」，就是违规。
2. **视觉语法**：不画写实食物（代码画的鸡腿永远像鸡腿emoji），改画**「价签货架」**——大价格数字、份量条、套餐托盘、门店门头牌。团购观众要的是「估出这份值多少钱」，信息图比写实图更有效。
3. **产能意义最大**：本机发布队列**只剩 5 条**（已发 88 条），`素材库/未剪素材` 目录已不存在，`prepare.js` 每轮只打印 `no source clips left`。代码画视频是**唯一不依赖源素材的产能**，能把断供问题从「等人给素材」变成「等商品卡」。
4. **数据证明必须改开头**：近 84 条作品**均播 156.7、整体完播 5.1%、5s 完播 12.4%、2s 跳出 63.8%**。行业线：2s 跳出 <35% 算优秀、5s 完播 >34% 才过推流门槛、整体完播 15% 才合格。现在的片子三项全在不合格区，**问题就在前 2 秒**，1 秒钩子不是审美选择，是数据倒逼。
5. **合规是硬闸门，不是建议**：《抖音生活服务 AIGC 创作规范》明确禁止「用 AIGC 虚构商品/门店/服务、夸大分量规格、生成虚假体验过程」，违规处置含限流、经营组件自见、扣信用分；2026 年一季度已处置 80 万条 AIGC 违规带货内容。所以本管线**只用商品卡里已有的事实**写文案，检测到缺字段就换钩子型，绝不补编。
6. **先小比例试水**：8 条/天里先占 **2 条**，跑 7 天看 2s 跳出 / 5s 完播 / 均播；数据赢了再加量，被限流立刻降量停用。**不一次性把实拍片替换掉**。

## 1. 调研结论

### 1.1 账号自己的数据（`runtime/publish/stats/report.md`，2026-11-16）

| 指标 | 本账号（84 条） | 行业参考线 | 判断 |
|---|---|---|---|
| 单条均播 | 156.7 | — | 流量池极小 |
| 整体完播 | 5.1% | 合格 15% / 优质 25% / 爆款 35% | 不合格 |
| 5s 完播 | 12.4% | 合格 20–30% / 推流门槛 34% / 爆款 40%+ | 不合格 |
| 2s 跳出 | 63.8% | 正常 40–60% / 优秀 <35% / 爆款 <25% | 比正常还差 |
| 涨粉 | +2 | — | 内容没人记住 |

品牌差异极大：好想来 2 条均播 121.5，椿田熟成茶行 4 条均播 16.3，**差 7.5 倍**。
时段差异：09–12 点均播 220.4，06–09 点 52.7 —— 排期已有加权，不属于本方案范围。

结论：**前 1–2 秒必须给结果（价格 / 份量 / 品类 + 地点）**，并且总时长压在 15 秒内，这是本管线所有设计的前提。

### 1.2 平台规则（必须落成代码规则，不是文案提醒）

| 规则 | 出处 | 对本管线的硬约束 |
|---|---|---|
| 达人团购视频**时长至少 15s**，且**至少口播讲解一道菜品** | 抖音生活服务《达人合作规范》5.5.2.4 | 主版固定 15.0s；口播必须点到具体商品，不能只喊品牌 |
| 视频中的商家信息、商品名、价格、菜品、预约方式、使用条件**必须与 POI/商详页一致** | 同上 5.5.2.3 | 所有数字只能来自商品卡；缺字段就不说 |
| **严禁绝对化用语**：最/最佳/第一/天花板/全网最低/仅此一家… | 《涉及绝对化用语》规则 | 内置禁词表，生成即拦 |
| **不得营造虚假紧迫感**：「最后一天」「马上下架」「限量抢购」「秒杀」「倒计时」 | 同上（2.8 条） | 禁词表 + CTA 模板白名单 |
| 价格必须真实，不得抬高划线价、不得用配菜/小食价格模糊宣传 | 商品通用规范 / 价格规范 | `orig_price` 必须有来源才显示划线价，否则只报团购价 |
| 不得出现销量截图、评价截图、店铺评分组件 | 商品通用规范 | 画面组件白名单，禁止"销量/好评"贴纸 |
| **AIGC 必须主动声明**；不得虚构商品/门店/服务，不得夸大分量规格，不得生成虚假体验过程 | 《抖音生活服务 AIGC 创作规范》 | 发布勾选 AI 声明；文案禁用第一人称体验（"我吃了/我去过/亲测"） |
| 发布前须勾选官方标签（含「内容含营销推广信息」「由 AI 生成」） | 2026-05 平台新规（业内口径，需在发布页实测核对） | 发布侧待办：核对是否有「内容含营销推广信息」勾选项 |
| 优质内容标准要「真实、有用」：真人交互、实拍，反例是宣传海报/团购页截图轮播 | 《生活服务营销内容质量分级体系》 | 本管线先天弱项；靠「决策信息密度」补，占比控量 |

> 直白说：纯 AIGC 片在「真实性」这一项拿不到满分，**只能靠信息密度和价格真实拿分**，不能靠"像实拍"骗过去。

### 1.3 爆款结构（融合平台公式与本地生活实操）

平台官方「起承转合」爆款公式：0–5s 痛点/场景 → 5–10s 卖点描述 → 10–20s 体验描述 → 20–30s 强制转化；五大信息 = 用户痛点 / 商品信息 / 产品卖点 / 适用场景 / 行动指令；六大元素 = 口播 / BGM / 字幕 / 字说 / 贴片 / 贴纸。
本地生活实操共识：**前 3 秒必须同时给品类 + 地点**，中段产品特写占一半以上，价格对照要具体数字，结尾明确指向左下角。

本管线压缩成 **15 秒 7 段**（见 §3.4 镜头表），因为我们的完播只有 5.1%，30 秒版先不做主推。

### 1.4 配音与语速

- 带货类口播常用 **5–5.5 字/秒（约 300–330 字/分钟）**；15 秒片口播 **70–84 字**（含 8–10 句、句间 120–160ms 停顿）。
- 语速可调 1.08–1.18 倍；同品牌锁定同一档，避免人设漂移。
- 品类音色倾向：炸鸡/烤肉类偏「热情利落」，茶饮/甜品偏「轻快亲和」，正餐/宴请偏「稳」。

### 1.6 技术验证（本机实测，2026-11-16 夜）

| 项 | 实测结果 | 对方案的影响 |
|---|---|---|
| Playwright 启动 | 默认会找 `chromium_headless_shell-1187`，**不存在 → 直接失败** | 必须传 `executablePath: …\ms-playwright\chromium-1243\chrome-win64\chrome.exe`；写进 `pipeline.json#render.chromium_path`，并保留 `chromium_path` 覆盖项 |

## 3. 视觉与时间设计

### 3.1 画面六层（「价签货架」）

```
L6  钩子卡 + 字幕（顶部 12–24% 钩子字，底部 73% 高处字幕，48px，黑描边 3px）
L5  门店层：门头牌 + 商圈字 + 到店箭头
L4  信息层：份量条 / 规格标签 / 等 N 店通用 / 无需预约 / 可配送
L3  商品层：SVG 矢量件（桶、杯、盘、盒、串、锅、蛋糕、生煎、饭团…12 个）
L2  价签层：团购价巨字 + 原价划线牌 + "省 X"（仅在有来源时）
L1  底色：墨底 #14110F + 品类色块（爆炸色只用于价签，不铺满）
```

- 品类色板：炸鸡汉堡 `#FF6A3D`、茶饮 `#2EE6A8`、咖啡 `#C98A4B`、火锅 `#E23A2E`、烘焙 `#F2B33D`、自助正餐 `#C9A227`。
- 价格数字统一：黄 `#FFD400`（沿用项目钩子卡定稿色）+ 黑描边，不用发光、不用渐变。
- **不用写实食物渲染、不接生图/生视频 API**。道具全部 SVG 代码画，同一 seed 可复现。

### 3.2 动效语法（对着「0.9 秒划走」设计）

- 0.00s 首帧就是钩子（**不是淡入**）：价签从上方砸下 + 数字 0.35s 内跳到目标值 + 音效「啪」。
- 之后每 1.2–1.8s 一次「事件」：贴纸弹出 / 划掉原价 / 印章盖下 / 托盘推入 / 门头推轨。
- 只硬切 + ≤0.12s 位移，禁止 0.3s 以上溶解转场（溶解＝观众划走窗口）。
- 所有元素启动时创建一次，`renderAt(t)` 只改属性；禁 `Date.now()` / `Math.random()`，随机走 `rng(seed)`。

### 3.3 钩子引擎（8 类模板，全部只用商品卡事实）

| 型 | 触发条件 | 公式 | 实例（真实卡数据） |
|---|---|---|---|
`P1` 价格直给 | price ≤ 15 | `{price}，{规格/件数}` | 「12块8，双拼6块」— 华莱士 12.8 |
`P2` 价格反差 | price + orig_price 且有来源 | `{orig}的东西，{price}` | 无来源不启用 |
`P3` 数量/组合 | items ≥ 3 或"N选1" | `{N}样，{price}` | 「19块9，3选1」— 椿田 19.9 |
`P4` 本地认领 | city/district 已知 | `{商圈}这家{品牌}，{卖点}` | 「吴江这家椿田」 |
`P5` 品类对号 | category 已知 | `{品类}控看这条` | 「奶茶控看这条」 |
`P6` 场景时段 | usage 含"可配送/无需预约" | `{场景}，{价格}` | 「下班路上，10块9」— 茉沏 10.9 |
`P7` 规格提问 | spec 明确 | `{规格}，你选哪个` | 「两种口味，你选哪个」 |
`P8` 兜底 | 以上都不满足 | `{品牌}，{商品}，{price}` | 「柠檬森林，鸭屎香柠檬茶，28块8」 |

选择顺序 P2 → P1 → P3 → P4 → P6 → P7 → P5 → P8；命中即停。
**禁词表**（生成后二次过滤，命中即换型）：最/最佳/最好/第一/唯一/天花板/顶级/全网最低/史无前例/仅此一家/最后一天/最后X小时/限量抢购/秒杀/倒计时/0元/免费下单/包退包赚。

### 3.4 15 秒镜头表（主版）

| 时间 | 镜头 | 画面 | 口播（示例，实际由槽位生成） |
|---|---|---|---|
| 0.00–1.00 | 钩子 | 价签砸落 + 巨字价格 + 品牌贴纸 + 音效「啪」 | 钩子句（≤12 字） |
| 1.00–3.00 | 认领 | 门头牌 + 商圈 + 「(XX店)」 | 品类 + 地点 |
| 3.00–4.50 | 套餐总览 | 托盘 3–4 个道具逐个弹入 | 套餐里有什么 |
| 4.50–7.50 | 卖点 1–2 | 单品框 + 份量条/规格数字 | 卖点（来自 items/spec） |
| 7.50–9.50 | 决策信息 | 「无需预约 / 可配送 / 等 N 店通用」逐条盖章 | 使用条件 |
| 9.50–12.00 | 价格锚点 | 原价牌划掉（有来源时）→ 团购价二次砸下 | 价格句 |

### 3.5 字幕规范

- 一行 ≤10 汉字，去标点，句末不留空格；底部 73% 高处；48px NotoSansSC-Bold / 描边 3px。
- 时间来自**实测音频的句边界**，不按字数均分。
- 字幕文本与 `meta.lines` 同一份数据，`daihuo.py qa` 用像素自证（见 §4.3）。

## 4. 自动文案 · 自动音色 · 自动出片

### 4.1 商品卡（唯一输入，唯一事实源）

`runtime/code-video/cards.json`，一张卡一条片：

```jsonc
{
  "id": "20261116-chuntian-heiwushi",
  "brand": "椿田熟成茶行",
  "category": "茶饮",
  "product_raw": "【明星爆品】招牌黑武士熟成薯丸3选1",
  "product_name": "招牌黑武士熟成薯丸3选1",     // 去掉营销括号后的归一化名
  "price": 19.9,                              // 必须等于商详价
  "orig_price": null,                          // 无来源就 null
  "orig_price_source": null,                   // "商详划线价 2026-11-16" 之类
  "items": ["黑武士薯丸", "熟成茶底", "3选1"],
  "spec": "3选1",
  "store": "椿田熟成茶行(苏州吴江万象汇店)",
  "stores_count": null,                        // 商详"等N店通用"有就填
  "city": "苏州", "district": "吴江",
  "usage": ["无需预约"],
  "validity": null,
  "delivery": false,
  "source": { "plan": "2026-11-16", "item": "2026-11-16-01", "captured_at": "2026-11-16T06:28:00Z" }
}
```

**自动积累**：`scripts/publish/` 的计划里已经存了 `product.selected / store / price / promo_title`（今天 8 条都齐），用 `code_video_cards.js` 从 `runtime/publish/plans/*.json` 反抽，人工只补 `items / orig_price / usage / stores_count` 这类平台没落的字段。**缺字段不是错，是降级**：缺 `orig_price` 就不出价格反差钩子。

### 4.2 文案生成（规则引擎优先，LLM 只做可选润色）

1. 归一化商品名：去「【】」营销括号、去「-可配送L121」这类后缀、去价格与标点（复用 `product_pick.js#productTerms` 的思路）。
2. 逐镜填槽：每个镜头有 2–3 个句式模板，槽位只允许从商品卡取值（`{brand}{product}{price}{spec}{city}{district}{store}{items[n]}`）。
3. 出 3 个候选 → 打分（钩子强度 / 信息密度 / 长度 / 与历史标题重复度）→ 选 1。
4. 过三道校验：**数字白名单**（每个数字必须能在卡里找到）、**禁词表**、**长度与字数**（15s 版 72–84 字）。
5. 任何一步失败 → 降级到 `P8` 兜底句式；兜底也失败 → 这张卡不出片（**宁可不出，不出错片**）。

> 为什么不用 LLM 直接写：平台禁止虚构，而 LLM 最爱把「19.9」写成「十几块」、把「3选1」写成「随便选」。规则引擎的错误率是可控的，LLM 的不是。

### 4.3 音色自动路由

`voice_map.json`（品类 → 音色档，同品牌锁定）：

| 品类 | 音色档 | 合成参数（GPT-SoVITS） | 说明 |
|---|---|---|---|
| 汉堡炸鸡 / 烤肉 / 火锅 | `dabao-hot` | speed 1.15 / temp 0.95 / gap 120ms | 利落、带劲 |
| 茶饮 / 咖啡 / 甜品 / 烘焙 | `dabao-light` | speed 1.12 / temp 0.92 / gap 140ms | 轻快、亲和 |
| 自助 / 正餐 / 宴请 | `dabao-steady` | speed 1.05 / temp 0.88 / gap 180ms | 稳、可信 |
| 未识别 | `dabao-std` | speed 1.10 / temp 0.90 / gap 160ms | 通用 |

- 主音色：`dabao`（`D:\GPT-SoVITS\voices\dabao\ref_dabao3-1.wav` + `preset.json`），自有克隆、零成本、有人味。
- 换语气不换人：`dabao_tts.py` 支持 `--speed / --temperature / --keep-gap-ms / --ref-audio`。**同一人不同情绪的参考片段**可作为第二档位（需大宝本人录 2–3 条 10 秒样本，属于待补素材，不是必须）。
- 第二音色（可选、默认关）：`edge-tts` 的 `zh-CN-XiaoxiaoNeural`，用于茶饮/甜品的女声 A/B；需 `pip install edge-tts` + 网络，且音质偏朗读腔，只做对照。
- **合规**：只使用自有/已授权音色，不克隆他人声音（AIGC 规范明令禁止未授权仿声）。

**配音流程**：
1. 整稿一次合成（句间 120–160ms），保音色连贯；
2. `silencedetect` / 能量包络切句 → 每句起止时间；
3. 切不准则退化为**逐句合成**（每句 ≤14 字，拼接 + 20ms 补静，时间轴 100% 准确）；
4. 崩词/漏读：`preset.json#speak_fixes` 追加同音替换；本机暂缺 faster-whisper，**每批人工抽听 2 条**兜底。

### 4.4 渲染与音频

- 渲染：`index.html` 单页 + `renderAt(t)` 协议，Playwright 逐帧 JPEG（q=92），**实测 84ms/帧 → 450 帧约 38 秒/条**；`node_modules` 做 junction 指向 `D:\@kaifa\tuangou\node_modules`（`.gitignore` 排除），`executablePath` 显式指向 `chromium-1243`。
- 音频：人声 1.0 + BGM 0.35–0.45（品类选曲）+ SFX（价签「啪」/金币双音/印章/蒸汽，纯代码合成，128 BPM 对拍）；`loudnorm I=-14 TP=-1.5`，AAC 48k，末尾 0.4s 淡出。
- 输出自检：1080×1920 / 30fps / 450 帧 / 15.00±0.1s / 0 黑帧 / LUFS −14±1 / TP ≤ −1.5。

## 9. 风险与不做什么

| 风险 | 影响 | 对策 |
|---|---|---|
| **平台真实性评级**（最大） | 纯 AIGC 信息型可能拿不到「优质」流量，甚至被判「非实拍」 | 不冒充探店；占比先 2 条/天；7 天看 2s 跳出/完播；被限流立即降量停用 |
| 价格合规 | 虚构原价/划线价 → 价格欺诈，平台与市监都管 | `orig_price` 无源不显示；发布前复核商详价 |
| 画面「画不像食物」 | 观众估不出价值 → 不转化 | 不画写实，画规格/份量/价格信息图；道具保持符号化 |
| 音色单一 | 8 条/天全是同一个声音，审美疲劳 | 品类四档 + 同品牌锁定；女声 A/B 可选接入 |
| 配音崩词 | 错字出片 → 违规风险 | 同音替换表 + 人工抽听；崩词不出片 |
| 本机缺 numpy | 字幕闸门 `unavailable`，新片卡住 | `code_video` 自证分支；或 P0 装 numpy |
| 生成抢 CPU | 影响 8 条/天的定时发布 | 生成放在低峰（07:10/11:10/15:10），单条串行，`gen_code.lock` 防并发 |
| 代码片挤掉实拍 | 账号内容结构单一，评级下滑 | 两类片在队列里打标，按比例出，不按"谁先谁发" |

**不做**：不替代实拍探店；不做 AI 真人/数字人出镜；不接云端生图/生视频（费用不可控、且与"代码确定性"冲突）；不生成销量/评价截图；不做"限时秒杀"话术；不自动发布（仍走现有闸门与人工首条验收）。

## 12. P0 实测记录（2026-11-17）

样片：`Auto-Video/daihuo/projects/000_p0_smoke/out/华莱士-双拼6块-CV-01.mp4`（真实商品卡：华莱士 12.8 双拼 6 块，苏州新桃源店）。

| 项 | 实测 | 与方案预估的差 |
|---|---|---|
| 配音 | 8 句 / 85 字 / 12.68s（v3 + dabao，speed 1.15、gap 140ms） | 语速约 6.7 字/秒，比方案写的 5–5.5 快；15s 片建议把 speed 降到 1.05–1.10 |
| 渲染 | 450 帧 34–36s，80ms/帧 | 与 38s 估测一致 |
| 音频 | −14.47 LUFS / TP −1.40 | 需**两遍** loudnorm，单遍会停在 −15 |
| 门禁 | 9 项全绿（含无 >0.5s 冻帧） | 静止帧是硬指标，必须靠连续运动压下去 |
| 字体 | 自带 NotoSansSC-Bold | 中文描边必须换 8 方向 text-shadow |

**P0 发现、必须带进 P1 的六条：**

1. `dabao_tts.py` 每次调用重启服务，模型加载 60–90s；批量生产用 `--keep-server` 或常驻 9880。
2. 句边界不能「取最长静音」——统一 140ms 后长度排序失效，会把某句拉成 5.3 秒；按字数比例取最近静音才对。
3. 只做入场动画 → 3 秒长镜头整段静止（freezedetect 抓到 0.9s 冻帧）；补「缓慢推近 + 背景光斑」才干净。
4. 入场放大必须 `transform-origin: 0% 60%`，否则首帧大价格自己裁出画面外。
5. Playwright 必须显式 `executablePath`（chromium-1243），默认 headless_shell 版本号对不上。
6. 首帧钩子可以机械验证：数 `#FFD400` 色块占比，样片 3.49% 达标（阈值 ≥1%）。
