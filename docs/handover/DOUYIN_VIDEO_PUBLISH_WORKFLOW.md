### 排期与库存

- day1=2、day2=4、day3=6、day4=8；day5 起每天随机 8–12 条
- 时间窗 09:00–22:30，相邻作品最小间隔 25 分钟；同日种子固定、可复现
- 随机时段按宝哥要求模拟真人发帖节奏，**不是绕风控**；遇到验证码/安全校验仍按原规则暂停交人工
- 计划任务：`TuangouPublish` 每 5 分钟执行 `run_due.js`；`TuangouPrepare` 每 30 分钟检查一次（全天运行）
- 库存不足（可用 < 剩余 + 2）时 `run_due.js` 拉起 `prepare.js` 调 `auto_edit.py --all` 补货；补货通知每小时最多一次。点击发布后结果未知时不自动重试，成片加 `_unverified_` 前缀移出自动队列并微信通知人工核实
- 空闲清库存（2026-11-01 宝哥新增）：只要 `素材库/未剪素材` 有素材就自动剪成成片。发布窗口外一次清完；窗口内仅当距下一个待发作品 60 分钟以上且无发布进行中，每次剪一条，避免占用 CPU 影响定时发布。刚复制进来的素材需稳定 2 分钟后再剪
- 剪完的源素材移入 `素材库/未剪素材/已剪`，成片进入 `素材库/已剪成片` 等待排队发布
- 文案质量闸门：片尾口播（点赞/订阅/打赏/栏目/感谢观看等）、纯英文、口吃重复、半句碎片会被过滤；常见 ASR 同音错字（豚→囤、买一送衣→买一送一、粉紫便便→粉紫渐变等）自动纠正；标题至少含一个卖点词，否则用 meta 里的商品名兜底；命中乱码/低俗词的成片整条不发，自动换下一条
- 品牌核验闸门（2026-11-02 宝哥要求）：成片无品牌、`meta.brand.needs_review=true`、或品牌置信度低于 `publish.brand_min_confidence`（0.9）时，一律跳过不发布，发微信「等待品牌确认」并列出跳过的成片；跳过后继续发下一条品牌能确定的，发布成功通知也带跳过名单；被跳过的成片留在库存，等宝哥人工审核确认品牌后再发。OCR 对仿品牌字不可靠（`11月1日_00791652.mp4` 被读成 McS/McSa，宝哥确认为肯德基），人工核验须联网多搜索到能确定品牌为止，仍不能确定就放弃该条，绝不猜着发

### 失败与暂停

- 验证码 / 安全校验 / 登录失效（还没点「发布」）：`state.json` 写 `paused: true` 并发 Windows Toast + 微信；成片留在队列，等宝哥扫码后人工恢复
- **点击「发布」之后一切异常都不重试**：此后遇到验证码、登录失效、页面跳动或结果未知，一律按「结果待核实」处理——计划标 `pending_verify`，成片加 `_unverified_` 前缀移出自动队列，同时推送「抖音发布结果待核实」；即使暂停也先移出队列，避免恢复后二次发布。改名失败时把成片写入 `state.excluded_videos`，`pickVideo` 同样会排除
- 已发布但内容管理显示「审核不通过」：计划标 `rejected` 并移出队列，推送「抖音作品审核不通过」
- 其他失败：最多重试 2 次；计划时间晚 180 分钟仍未发则标 `skipped`
- 发布日期日志：`runtime/publish/logs/YYYY-MM-DD.log`；截图：`runtime/publish/shots/`

## 固化规则（2026-11-01）

### 1. 封面：必须等横封面 4:3 生成完成

选择「AI智能推荐封面」列表中的目标封面后，页面会自动生成两套封面：

1. 竖封面 3:4（先生成）；
2. 横封面 4:3（通常晚于竖封面，需要等待）。

**判定标准**：两个封面预览框都显示出生成后的画面（本次为封面文字「两款奶茶选哪个」「每次都好纠结」）才算封面完成。只看竖封面已生成就继续填表，会误判封面已完成。

- 等待期间不做其他填表操作；若长时间仍为空，重新点选同一张推荐封面，不要换成其他封面。
- 用户指定「第一张」时，只选第一张，不擅自更换。

### 2. 标题与描述：按团购博主的口语化写法

学到的常见套路（来自公开的短视频标题/本地生活运营资料）：

- 标题多控制在 10–20 字，口语化，最常见的是**疑问句 / 二选一悬念**，用提问引导评论；同时带品牌或商品关键词便于搜索。
- 描述是「**场景钩子 → 商品与规格 → 互动提问**」三段式，不写成商品说明书。
- **描述结尾不要再写「具体商品信息、适用门店和使用规则请以团购页面为准」这类免责句**（2026-11-01 用户明确要求）。商品信息以团购页面展示为准，不在文案里重复。
- 避免绝对化用语（最好、第一、唯一、最正宗）和无法证实的口感/功效宣称。

本次定稿（已填入页面并核验）：

- 标题（19/30）：`上班偷偷点的柿柿可利，二选一你站哪杯？`
- 描述（97/1000，含话题）：

```
上班偷偷点了一杯爷爷不泡茶的柿柿可利，柿柿椰椰和柿柿有杏两款可以选，选哪杯就看自己更喜欢哪种搭配。我是每次都纠结，你们更想要哪一款？
```

写作约束：

- **标题和描述不能雷同**：同一篇里标题与描述不要互相复述（例如描述开头再写一遍标题的「上班偷偷点」）；不同作品之间只复用结构、不复用句子或整段模板。每条按视频口播和商品重新组织语言。该规则自 2026-11-01 起对后续作品生效；已发布作品不回溯修改（用户确认）。
- 内容必须与视频口播事实一致；口播没说的细节（具体时间、价格、销量、亲测结论）不补写。
- 不加「具体商品信息、适用门店和使用规则请以团购页面为准」这类免责句。
- 话题 3–5 个：品牌 + 商品名 + 口味 + 品类。

### 3. 话题标签

在描述末尾逐个输入「`#` + 话题 + 空格」，确认页面渲染为话题标签（浅蓝胶囊背景），而不是纯文本。

本次 5 个：`#爷爷不泡茶`、`#柿柿可利`、`#柿柿椰椰`、`#柿柿有杏`、`#饮品团购`。

注意：直接用鼠标点击描述框空白处可能把光标放进正文中间；先在末尾定位（Ctrl+End）再追加。

## 页面状态验证方法

无浏览器自动化工具时，用系统级截图 + 本地 OCR + 像素判别，避免仅凭「点过了」判断成功：

- 坐标映射：全窗口截图缩到 1900 宽，记录 `left/top/scale`；屏幕坐标 = `left + 图片坐标 / scale`。点击前必须重新截全窗口，避免旧缩放导致偏移。
- 文本核验：本地 OCR（`D:/@kaifa/Dabao-OCR`）读标题、描述、计数器；必要时聚焦输入框 Ctrl+A/Ctrl+C 读剪贴板纯文本。
- 单选状态：像素判别。选中项是深色粗圆环（中心留白），未选中项是浅灰细环；在 21×21 区域内统计深色像素（R/G/B 均 <80）。本次「不同时发布」为 356 个、「同时发布到」为 0 个。判定前先用同组默认选中项（如「公开」「允许」）校准样式，避免把深色圆环误判成空心。
- 话题标签：话题胶囊背景为浅蓝（RGB 219,233,250），正文区背景为（249,249,250）；据此区分标签与纯文本。
- **表单重渲染会重置自主声明**：确认封面等操作后，必须回到自主声明再核验一次；本次复核仍为「内容由AI生成」。
- 复核顺序：文案与话题 → 竖/横封面 → 自主声明 → 位置门店 → 发布设置；未获批准时最后确认未发布，获批准则转入「发布与发布后核实」。
